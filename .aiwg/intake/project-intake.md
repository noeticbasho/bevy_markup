## System Overview

A Bevy 0.20 library that turns HTML templates (Tera, or Markdown), CSS and Fluent localization into native Bevy UI entities, with 9-slice frames as CSS `border-image`. Apps spawn an `HtmlUi` with a template and a `TemplateContext`; the library renders, localizes and builds the entity tree, then updates it in place when the context, stylesheet, locale or interaction state changes. Declarative interaction (`data-on-*` signals, `:hover`/`:focus` restyles), focus and directional navigation, tooltips and anchored overlays, forms and text input are built in. It is the UI layer of the studio's games (prototype_19) and apps (vtuber).

## Problem and Outcomes

- Author game UI the way the web does (templates, stylesheets, translation files) instead of hand-built Bevy node trees.
- Keep the library to that mapping (ADR 0002): minimal Bevy features, app decisions (input bindings, fonts, panels) stay in apps.
- Verify the mapping against reference implementations (Chromium, `@fluent/dom`) and attack it with generated input (ADR 0004).

## Architecture (Current State)

A `PostUpdate` pipeline in three chained sets (`HtmlUiSystems::{Render, Localize, Build}`) before Bevy's `UiSystems::Prepare`: render the Tera template, parse it (`astral-tl`), localize with Fluent, cascade the CSS (`lightningcss`), and reconcile a `NodeSpec` tree with the existing entities. When to update is decided by a pure state machine (`rebuild` module, ADR 0005). Details: @AGENTS.md ("Public API", "Layout", "Pipeline").

## Scale and Performance (Current)

Measured with criterion (600 elements): changing content 1.17 ms with subtree reuse (2.09 ms without), markdown 6.27 ms (ADR 0021). Benchmarks (criterion, divan) run nightly; hotpath profiling has a regression policy (`hotpath/policy.toml`). Long scrolling documents build only the visible band (ADR 0031–0033).

## Security and Compliance (Current)

- Template, CSS, Fluent and Markdown input are treated as untrusted: anything reachable from user data that panics is a high-severity bug; fuzzed by cargo-fuzz (`css`, `html`, `ftl`), honggfuzz, fuzzcheck, test-fuzz and arbtest.
- Two upstream `fluent-syntax` defects (a panic, a stack overflow) are fixed in a fork applied with `[patch.crates-io]`; apps must add the same patch (README). Upstream PRs pending (`UPSTREAM.md` U1, U2).
- The `dev-tools` QA surface (localhost BRP + MCP) is never enabled in a shipped build.
- MIT OR Apache-2.0.

## Known Issues and Technical Debt

- The nightly workflow has failed every night since 2026-10-14 (2026-10-28: browser oracle drift, a css fuzz timeout, a stack overflow in the coverage job's corpus replay); not triaged.
- `flex-shrink` defaults to 0, not CSS's 1: copied browser CSS misbehaves silently (bug_0028; open design question).
- `CHANGELOG.md` has a large `[Unreleased]` section since 0.7.0; prototype_19 is still on 0.4.0.
- Known limits per area (layout, selectors, inline boxes, text, fonts): @AGENTS.md "Limits and next steps".
