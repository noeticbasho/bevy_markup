## Symptoms

```css
p { color: hsl(1e39 50% 50%) }
```

In a debug build the parse panics: `assertion failed:
(0.0..=1.0).contains(&hue)` at `cssparser-color-0.5.0/lib.rs:308`.
Also `hwb(1e39 2% 8%)`, the comma syntax, `hsl(calc(infinity) 50% 50%)`,
the same colours in a custom property (`--x: hwb(1e55 2% 8%)`), in a
`style` attribute, and in a context variable substituted into
`hsl(var(--h) 50% 50%)`. Finite hues of any size (`1e30`, `-1e30`) and
`calc(NaN)` are fine. Release builds don't panic.

Where it lands: a sheet's load fails through Bevy's `AssetLoaderPanic`;
a `style` attribute or a substituted value panics the build system, on
the app's main thread.

## Minimal reproduction

The line above as a stylesheet, or `<p style="color: hsl(1e39 50% 50%)">`.
The fuzzer's input was 173 bytes of binary around
`hwb(1111111111111111111111111111111111111111111111111111111 2 8 …`.

## Root cause

`1e39` is infinite as `f32`. lightningcss normalizes a hue with
`(h - 360 * (h / 360).floor()) / 360` (`values/color.rs`, `From<HSL> for
SRGB`), which is NaN for an infinite `h`, and passes it to
cssparser-color's `hsl_to_rgb`, which starts with
`debug_assert!((0.0..=1.0).contains(&hue))`. The conversion runs at
parse time, for legacy `hsl()`/`hwb()` colours wherever lightningcss
tries a colour — typed properties and custom-property token lists alike.

## Fix

`cascade::guarded_parse` runs the three lightningcss parses the crate
makes on untrusted text — `StyleSheet::parse` in the loader,
`StyleAttribute::parse` for `style` attributes, `Property::parse_string`
for substituted `var()` values — under `catch_unwind`, as `svg::guarded`
does for usvg and resvg (UPSTREAM U20). A panic is an error: the sheet
fails its load with `the CSS parser panicked: …`, the attribute or the
declaration is dropped, the same outcomes as unparseable CSS.

A load-time scan was considered and not used alone: an infinite hue is
also reached through `calc()` arithmetic (`calc(3e38 * 3e38)`) and the
relative-colour syntax, so refusing every route means evaluating the
expression or refusing `calc()` in hues. With `panic = "abort"` nothing
catches it; such builds are normally release builds, which don't assert.

The fuzz harness (`fuzz::cascade`) parses through the same guard, and
the drivers' aborting panic hooks excuse exactly this assertion
(`fuzz::is_known_upstream_debug_panic`, pinned to cssparser-color
0.5.0), as for U20.
