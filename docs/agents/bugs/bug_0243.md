## Symptoms

Flat calls passed the nesting limit. The release pre-check took
14.8 ms for 5,000 arguments, 59.6 ms for 10,000 and 237 ms for 20,000.
The real debug bundle load accepted the largest resource (1.78 s
including app setup/settling). No formatting or registered function is
needed to incur the work.

## Minimal reproduction

```python
n = 20_000
ftl = 'm = { FUNC(' + ', '.join(f'a{i:06}: 0' for i in range(n)) + ') }'
```

Load it from `(locale: "en-US", resources: ["m.ftl"])`.

## Root cause

The checker ports fluent-syntax's `Vec::contains` duplicate-name
scan. Each argument scans all earlier names. Bounding recursion does
not bound the width of a flat call, and replacing only this crate's scan
would leave the upstream parser exposed.

## Fix

Before parsing each argument, reject calls past
`MAX_FTL_ARGUMENTS` (64), returning `TooManyArguments` with a line and
limit-naming message. The combined positional/named limit applies per
call, including nested and term calls. Both this checker and the
subsequent upstream scan are bounded. See ADR 0047 and UPSTREAM U47.

## Validation

The new review_0009 regressions pass with the fixes. With the fixes
removed (for FTL, retaining the new error type but disabling enforcement),
all eight new regression tests failed, including the real-loader and
focus/activation tests. After committing `364d734`, every command in `.github/workflows/ci.yml`
passed, including the Fluent oracle comparison (16 command results).
Three commands initially ran out of disk space while linking; all passed
on retry after removing only the rebuildable incremental compiler cache.
Honggfuzz then completed a 900-second campaign on each of `html`, `css`,
`ftl` and `svg` (two workers each, pinned `nightly-2026-09-09`), reporting
zero crashes and zero timeouts on all targets. See review_0009's final
validation table for iteration counts and log locations.
