## Symptoms

```xml
<g fill='url(#p)'>
  <pattern id='p' width='10' height='10' patternUnits='userSpaceOnUse'>
    <rect width='5' height='5'/>
  </pattern>
  <rect width='64' height='64'/>
</g>
```

AddressSanitizer: stack-overflow, inside usvg's conversion. In a normal
build that's a process abort, which `svg::guarded` can't catch.

## Root cause

The pattern's `rect` inherits `fill='url(#p)'` from the group around the
pattern. Converting the pattern converts the rect, whose fill converts the
pattern again, and so on: usvg has no guard against a paint server
reached through inheritance. The depth check's graph had only explicit
references as edges, so it saw no cycle.

## Fix

The inheritance walk gives every shape and text element an edge to each
paint server and marker it inherits. The pattern's rect now has an edge to
the pattern, which is its ancestor: a cycle, refused with
`SvgError::ReferenceCycle` before usvg runs. A marker that inherits itself
is refused the same way, although usvg would skip it. The CSS spelling of
that, `path { marker-end: url(#a) }`, was already refused through an
explicit edge.
