| field | value |

## Symptoms

```
{% component wrap() %}{{ body }}{% endcomponent %}
{% set_global s = 'aaaaaaaa' %}
{% for i in range(end=N) %}{% <wrap> %}{% set_global s = s ~ s %}{% </wrap> %}{% endfor %}
[{{ s | length }}]
```

| N | check | render |
|---|---|---|
| 16 | accepted | `[524288]` |
| 20 | accepted (output bound 146 bytes) | `[8388608]` |
| 100 000 | accepted (1 000 005 steps, 3% of the budget) | not run: N = 40 already asks for 8 TB, bug_0220's abort |

Without the component the same loop is refused (`Superlinear`).

## Root cause

`carried` finds a loop's `set_global` targets through `if`, `for`,
captures, blocks and includes. A component call with a body is
`Node::Expr(Expr::Component { body })`, which `carried` doesn't enter.
The body runs in the caller's scope, both in the analysis
(`self.nodes(body, env)`) and in Tera, so its `set_global`s carry
across iterations unseen and the growth check never runs on them.

## Fix (proposed)

`carried` walks expressions too (a component body is the only place
statements sit inside one). Test: the probe above refused, plus a
property that every statement position reaches `carried`.
