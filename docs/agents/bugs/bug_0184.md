## Symptoms

The property failed with cssparser nesting 9 `(` blocks, past
`MAX_CSS_PAREN_NESTING` (8), in text the pre-scan let through. Minimized:

```text
(*/url(\( \)light-dark(light-dark((light-dark(light-dark(\\75rl(light-dark(light-dark(
```

The core is `url(a \)`. In a declaration lightningcss tolerates, the
nested functions after it parse in exponential time: `p { --x: url(a \);
color: light-dark(…` takes 49 ms at 18 levels, 0.58 s at 22 and 2.3 s at
24 (release, lightningcss 1.0.0-alpha.72, Ryzen 7 9800X3D), about ×4 per
two levels. With the URL directly in the `color` value, lightningcss
gives up in microseconds.

## Root cause

The pre-scan treats an unquoted `url(` as one token, so closers inside
it close nothing. It found the token's end with one rule: skip to the
next `)`, a `\` skipping the byte after it. cssparser 0.37
(`tokenizer.rs` `consume_unquoted_url`) has three states:

| state | `)` | whitespace | `\` | quote, `(`, non-printable |
|---|---|---|---|---|
| body | ends the URL | → end state | a whole escape (hex digits and one whitespace); `\` + newline → bad URL | → bad URL |
| end (`consume_url_end`) | ends the URL | skipped | **consumed as a plain byte** → bad URL | consumed → bad URL |
| bad (`consume_bad_url`) | ends the URL | — | skips a following `)` or `\` only | — |

In `url(a \)` the space moves to the end state, which consumes the `\`
unescaped; the bad URL then starts at `)` and ends there. The pre-scan
treated that `\)` as an escaped `)` and ran on to the next `)`, or to
the end of the text, hiding every opener in between. The reverse can't
happen: where cssparser escapes, so did the pre-scan.

## Fix

`css_unquoted_url_end` and `css_bad_url_end` (`src/cascade.rs`) follow
cssparser's three states. The body consumes escapes with `css_escape`
(bug_0183's `consume_escape`), so `\41 \)` keeps the `\)` inside, as
cssparser does.

## Notes

The property found this on a random seed, not in CI: bug_0183's run
used other seeds. The generator lacked the bytes that reach the bad-URL
state from the body (tab, `\x01`, `\x7f`); they're added.
