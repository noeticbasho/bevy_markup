## Symptoms

| start tag | `color` added |
|---|---|
| `<svg viewBox="0 0 1 1">` | yes |
| `<svg class="icon color accent" …>` | **no** |
| `<svg aria-label="pick a color here" …>` | **no** |
| `<svg class="x xmlns y" …>` | yes, but **no `xmlns`** (usvg needs the namespace) |

The icon then ignores the cascade: black where the page says gold, no
`:hover` recolor. Only middle words trigger it (`class="color x"` and
`"x color"` keep their quote).

## Root cause

`prepare_inline`'s `has` splits the start tag on whitespace and compares
each piece up to `=` (`svg.rs:800-804`). A quoted value with spaces
splits too, and a bare word in its middle reads as an attribute name.

## Fix proposed by the review

Read the attributes with a quote-aware scan (`normalize_self_closing`
has one).

## Fix

`attribute_names` reads the start tag's attribute names the way HTML's
tokenizer does (quoted values skipped whole, unquoted values up to
whitespace or `>`), also finding the tag's end by it (a `>` inside a
quoted value no longer cuts the tag).
