## Symptoms

The invisible button received initial `InputFocus` and activation
emitted `hidden`, even though Tab order contained only `shown`.
Hiding the already-focused control had the same eligibility mismatch.

## Minimal reproduction

```html
<button id="hidden" style="display:none" data-on-click="hidden">Hidden</button>
<button id="shown" data-on-click="shown">Shown</button>
```

Settle an `HtmlUi` of this page and call
`HtmlFocus::activate(ActivationInput::Synthetic)`.

## Root cause

`sync_navigation` excluded `display:none` only from `TabIndex`,
while directional membership, initial/remembered/autofocus selection
and focus repair used the broader navigation set. Visibility checks
alone did not read `Node::display`.

## Fix

A shared `eligible` predicate checks both visibility and display in
hierarchy for navigation membership and focus repair. Tab order uses
that same membership. The initial fallback uses the same predicate;
remembered/autofocus selection sees only eligible members. Hidden modal
roots no longer take the modal scope. Explicitly focused link spans
retain their support, with display checked on their containing nodes.

## Validation

The new review_0009 regressions pass with the fixes. With the fixes
removed (for FTL, retaining the new error type but disabling enforcement),
all eight new regression tests failed, including the real-loader and
focus/activation tests. Full CI and a 15-minute honggfuzz campaign are
run after committing the fixes, at the user's request; their results
are reported by the fix session, not assumed here.
