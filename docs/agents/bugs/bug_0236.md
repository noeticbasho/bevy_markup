## Symptoms

`path = Folder C:\użytkownik` and `cmd = Wpisz \użyj w konsoli`: the
check refuses the resource, though fluent-syntax parses both. The loader
then fails the whole bundle, so every string falls back. `C:\usługi`
and `C:\users\anna` pass. Words starting `uż`, `uč`, `uç` after a
backslash occur in Windows paths and command names in Polish, Czech and
Turkish help text.

## Root cause

`bad_escape` scans the whole file, text included (ADR 0045 says so and
calls the false refusal rare). fluent-syntax only reads escapes inside
string literals, so in text a `\u` is plain characters.

## Fix

The file-wide scan is gone. The port's `skip_unicode_escape_sequence`
— reached only from string literals, where fluent-syntax's is — refuses
an escape that stops at a non-ASCII byte (`Stop::BadEscape`), exactly
the case fluent-syntax's error slice panics on. Text keeps `\u` as
plain characters.
