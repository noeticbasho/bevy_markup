## Symptoms

Layout harness; `p { width: 200px } img { width: 50% }`, `frame.png`
32 × 24:

| `UiScale` | inline box (logical) | expected |
|---|---|---|
| 1 | 100 × 75 | 100 × 75 |
| 2 | **200 × 150** | 100 × 75 |
| 0.5 | **50 × 37.5** | 100 × 75 |

The same on a HiDPI display at `UiScale` 1.

## Root cause

`size_images` resolves a percentage against `block.size` minus the
insets — `ComputedNode`'s **physical** pixels — and writes the result to
`InlineBox::size` and `InlineImage::width`/`height`, which are
**logical** (`rasterize_svg_images` divides the same box by
`inverse_scale_factor`). review_0006 J03 (bug_0153) was the same mix in
the windowed build. Every `%` image test runs at scale 1.

## Fix proposed by the review

Multiply `content` by `block.inverse_scale_factor`. Add a scale-2 case
for inline images (the harness's scale-2 camera from bug_0153 exists).

## Fix

`size_images` multiplies the content box by the block's
`inverse_scale_factor`: percentages resolve against the logical content
box.
