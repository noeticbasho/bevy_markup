## Symptoms

At the end of a windowed UI's scroll, every row sat a few px off the
full build (the first seed: `p55` at y 93 instead of 96, frame 0, margin
0). The relative positions all agreed; the windowed document's *scroll
range* was 3 px longer, so the clamped end offset was 3 px further down.

The first report blamed a dropped `.sec` row gap (3 px, like bug_0151).
That was a coincidence of numbers: the 3 px was the last row's
`margin-bottom`.

## Reproduction

Seed `17702137485556457484` (in the regressions file): the document ends
with `<p class="p h1">row 56</p><p class="p h1 m">row 57</p>` (`.m` =
`margin-bottom: 3px`); after `v = 5 chars; scroll 6094`, frame 0 of the
content build culls the tail into one spacer.

Minimized (`a_culled_run_adds_what_its_rows_add_to_the_scroll_range`):
40 rows, windowed with margin 0, scrolled to 0. The tail is culled and
the root's content height is 1278 windowed vs 1275 full. The range check
then found two more shapes on other seeds:

- seed `7307673853095145470`: the document ends with a section whose only
  row is `{% if not f %}`'d away. The empty section adds nothing, but the
  spacer covered the root's 2 px gap before it.
- seed `7307673853095171432` (proptest didn't save its hash; the
  minimized test covers it): a fixed-height row (`h1`, 37 px) whose
  wrapped `{{ v }}` text runs 17 px past its box. The full range includes
  the overflow, but the spacer ended at the margin box (3 px short).

## Root cause

A culled run became one spacer node whose height was the run's margin
boxes plus gaps. Layout matched, but the scroll range didn't. Bevy's
`ComputedNode::content_size` is taffy 0.14's scrollable overflow, and
`compute_scrollable_overflow_contribution` takes each child's **border
box** (or, with visible overflow, the overflow beyond it), never its
margins, and nothing from a box whose extent is empty. A spacer made all
of its run count as border box:

- a trailing margin (and the gaps before trailing empty boxes) became
  range;
- overflow past the members' margin boxes was lost.

## Fix

The height model records each subtree's **reach** next to its outer
height: how far below its margin-box top it extends a scroll range, with
the same rule as taffy (`margin_top + max(border box, content_size)` with
visible overflow, else the border box; `None` for an empty extent). A
coalesced run's reach is its furthest member's. The spacer node is
exactly `reach` tall, and its bottom margin is the rest of the run's
height, negative when overflow reaches past it. So it takes the run's
space in the column and adds the run's range. A reach change alone marks
the model changed, like a height change.

`Pair::scroll` now asserts in every settled frame that the windowed and
full roots' content heights agree within 1 px (it found the second and
third shapes). 400 cases in release pass with it.
