## Symptoms

```xml
<path d='M0 0 A1e9 1e9 0 1 1 1e9 0 A1e92 1e9 0 1 1 0 0'/>
```

ASan/libFuzzer: `out-of-memory (malloc(30064771072))` in
`svgtypes::SimplifyingPathParser` (`path.rs:987`) under usvg's
`convert_path`. The work bound had passed the document: it counted the
second arc as one cubic.

## Root cause

`arc_curves` replays kurbo's arc arithmetic from the exact current point,
`(1e9, 0)`. The simplifier starts the second arc where the first arc's
last cubic ended, `(1e9 + 5e-6, -2.9e-6)`. With `rx = 1e92` against a
chord of 1e9, that rounding error decides the sweep: from the exact point
it is ~1e-84 rad (one cubic), from the simplifier's ~3·10¹⁵ cubics. The
bug_0190 fix handled the rounding only for an arc that ends where it
starts (a whole turn).

## Fix

The sweep is at most a whole turn, so an arc whose radius after kurbo's
scale-up gives more than `EXACT_SWEEP_SUBDIVISIONS` (16) cubics per turn
(radius above ~1.5·10⁶) counts the whole turn. Below that, a misjudged
sweep is off by at most 16 cubics, the cost of a few line segments, so
ordinary arcs keep their exact count. Radii past ~1e77, where kurbo's
arithmetic can turn NaN (0 cubics), now count an infinite turn and are
refused.
