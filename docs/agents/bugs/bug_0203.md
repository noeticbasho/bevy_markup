## Symptoms

An inline image (`<img>`, inline `<svg>`) taller than the font's ascent
makes its line too short and sits above the line's top. At 20px
(line height 24), a 40px image in `<p>Tall <img> icon</p>`:

| | paragraph height | image top (from the paragraph's) |
|---|---|---|
| Chromium | 45 | 0 |
| bevy_markup (Bevy 0.20) | 40 | −3 |

The paragraph above is overlapped by 3px and everything below sits 5px
higher than in a browser. Images no taller than the ascent match the
browser to the pixel (the `layout_svg` vector keeps to those).

## Root cause

parley 0.11's `finish_line` treats an in-flow inline box's whole height
as ascent (`ascent = max(ascent, box height)`), while the line height is
the running maximum of the clusters' and boxes' heights
(`running_line_height`). For a box taller than the line height the
leading `line_height − (ascent + descent)` is negative (−descent), half
of it goes above the line, and the box rises by half the text's descent;
the text's descent never adds to the line. In CSS the line box spans
from the highest top to the lowest bottom of the strut and the boxes
around the shared baseline: the box's height above the baseline plus
the strut's part below it (40 + 5).

## Fix

None in bevy_markup: Bevy places the box from parley's line metrics, and
bevy_markup only sets the box's size. parley 0.12.0 (2026-10-09)
replaced these metrics with CSS line-box computation (`vertical-align`,
baseline-relative box extents). It's fixed once Bevy depends on it; then
run the ignored test and un-ignore it.
