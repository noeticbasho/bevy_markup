## Symptoms

A 4096 × 4096 document, one `<text font-size='3000'>` of N `M`s each
placed at `x='0'`, release build:

| glyphs | bytes | estimate | draw |
|---|---|---|---|
| 50 | 267 | 33 554 560 (25%) | 94 ms |
| 200 | 717 | 33 554 560 | 224 ms |
| 800 | 2 517 | 33 554 560 | 710 ms |

The estimate doesn't move with the glyph count. 800 `<rect>`s of one
glyph's box are refused (estimate 136 157 992). The work bound charges
text 16 units per byte, so it admits ~524 000 glyphs: about 7 minutes
at 0.85 ms each.

## Root cause

bug_0204's: `CostWalk` charges a text node `NODE_COST` and never walks
its flattened glyph paths. Without a pattern the drawing is merely
unbounded instead of aborting.

## Fix (proposed)

The same as bug_0204's (walk `text.flattened()` in `CostWalk`).
