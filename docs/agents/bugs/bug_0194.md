## Symptoms

```xml
<svg xmlns='http://www.w3.org/2000/svg' width='64' height='64'>
  <path d='M603553400 -786566100 L-232962910 303603170 L554380750 -829689350 Z'/>
</svg>
```

Debug builds: `assertion failed: edges[curr_idx].last_y >= curr_y as i32`
(`tiny-skia` `scan/path.rs`). Release builds: `called Option::unwrap() on
a None value` in `alpha_runs.rs`, or a slice out of range in
`pipeline/mod.rs`. A cubic crossing the canvas around 2·10⁶ px panicked in
`edge_clipper.rs` instead (`NormalizedF32Exclusive::new(1.0).unwrap()`).
`svg::guarded` turned each into `SvgError::Panicked`, a failed load. The
fuzz target aborted on them.

ADR 0040 recorded U24 as debug-only ("release builds skip it"). That was
wrong: the assertion is debug-only, but the overflow behind it isn't.

## Root cause

Two defects in tiny-skia 0.12.0, both only for paths far off the canvas:

- **The anti-aliased row range wraps** (U24, U28). `scan/path.rs` takes the
  path's integer bounds *before* clipping (its own `TODO: SkScanClipper`;
  Skia clips first) and shifts them left by 2 for 4× supersampling. Past
  |y| ≥ 2²⁹ that wraps an `i32`, and the edge walk starts at a garbage row:
  the debug assertion, or in release, writes outside the canvas that later
  `unwrap`s and slices catch.
- **The cubic clipper's search can't converge** (U27).
  `edge_clipper.rs` `mono_cubic_closest_t` bisects for the `t` where a
  cubic crosses the canvas edge, to a 0.25 px tolerance. Between ~2²¹ and
  2²² the f32 spacing is 0.25 px or more, so `t` walks to exactly 1.0 and
  `NormalizedF32Exclusive::new(1.0).unwrap()` panics. Above 2²²,
  `too_big_for_reliable_float_math` draws a line instead.

## Fix

After usvg's conversion every coordinate is a plain number, so the loader
measures how far the drawing reaches in image pixels before drawing
(`check_extent`). It walks the tree as resvg renders it: group transforms,
clip paths, masks, `feImage`, pattern tiles and text outlines. Each path's
control-point bounds count, padded by its stroke width × max(miter limit,
√2) / 2. A reach past `MAX_SVG_EXTENT` = 2¹⁹ px (128 × `MAX_SVG_SIDE`)
fails with `SvgError::TooFarOut`.

The limit was set by testing: 10,000 random paths per magnitude (10⁵ to
10⁷; lines, quads, cubics, arcs, random strokes and miter limits, a third
with `crispEdges`), each drawn when within the limit: no panic. Without
the limit, the smallest panicking reach seen was ~1.8·10⁶ px (U27).

The `svg` fuzz target stopped excusing the tiny-skia assertion. A
tiny-skia panic now means the extent check missed a case.
