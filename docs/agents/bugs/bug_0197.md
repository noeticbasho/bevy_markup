# bug_0197 — A filter on a shape wider than ~2.8·10³⁸ panicked tiny-skia-path during conversion

| field | value |
|---|---|

## Symptoms

```xml
<filter id='f'><feOffset/></filter>
<rect width='3e38' height='8' filter='url(#f)'/>
```

Every build: `called Option::unwrap() on a None value` in tiny-skia-path
0.12.0 `rect.rs:691` (`NonZeroRect::bbox_transform`), called by usvg's
filter conversion. With `width='2e38'` usvg converts and the extent check
refuses the drawing (`TooFarOut`).

## Root cause

The default filter region is in `objectBoundingBox` units (−10%, 120%).
usvg maps it onto the element's box with `bbox_transform`, which multiplies
and unwraps `NonZeroRect::from_xywh`: 1.2 × 3·10³⁸ is infinite (UPSTREAM
U31). The same unwrap serves every box-unit region (gradients, patterns,
clip paths, masks); only the filter case was run.

## Fix (open)

A pre-conversion bound needs the object bounding box, which comes from the
geometry and every transform inside the element's subtree (`scale(1e20)` in
a filtered group grows the box without any big number). Options: bound
each geometry number and each transform scale so that products stay below
`f32::MAX / 2` within the depth limit, or compute a coarse box bound in
`svg_bounds`. Until then, `svg::guarded` makes it a failed load.
