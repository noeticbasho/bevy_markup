## Symptoms

```xml
<filter id='f'><feOffset/></filter>
<rect width='3e38' height='8' filter='url(#f)'/>
```

Every build: `called Option::unwrap() on a None value` in tiny-skia-path
0.12.0 `rect.rs:691` (`NonZeroRect::bbox_transform`), called by usvg's
filter conversion. With `width='2e38'` usvg converts and the extent check
refuses the drawing (`TooFarOut`).

## Root cause

The default filter region is in `objectBoundingBox` units (−10%, 120%).
usvg maps it onto the element's box with `bbox_transform`, which multiplies
and unwraps `NonZeroRect::from_xywh`: 1.2 × 3·10³⁸ is infinite (UPSTREAM
U31). The same unwrap serves every box-unit region (gradients, patterns,
clip paths, masks); only the filter case was run.

## Fix

ADR 0042, at the user's suggestion: usvg computes the boxes itself, in a
first conversion of a rewritten copy that converts no filter, mask or
pattern (`svg_boxes::largest_box`): CSS inlined in usvg's order, each
`style` starting with `!important` `filter`/`mask`/`clip-path: none`,
`fill: #000`, `stroke: none`, and `defs`/`mask`/`clipPath`/`pattern`
renamed to `g` so their content converts in place. The largest box
coordinate, with the largest region factor from the XML
(`Bounds::regions`), decides `check_regions`: `SvgError::RegionOverflow`
when the worst product could overflow `f32`. The pass runs only for
documents with a filter, mask or pattern (`shadowed` bench: 4.4 → 11.4 µs).
