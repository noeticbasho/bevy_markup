## Symptoms

Release build; all drawn, none refused:

| document | estimate (of `MAX_SVG_COST`) | draw |
|---|---|---|
| 4 lines, 10⁶ dashes each, butt caps, width 1 (bug_0205's case) | 47% | 135 ms |
| the same, round caps, width 10 | 47% | 10.7 s |
| the same, round caps, width 40 | 48% | 33.0 s |
| the same, square caps, width 40 | 48% | 1.84 s |
| one path of 10⁶ zero-length subpaths, round caps, width 40 | 37% | 28.8 s |
| the same, width 200 | 38% | 107 s |
| one filled path of 10⁶ segments, each 4 096 px tall | 55% | 57.1 s |
| the same path stroked, width 30 | 56% | 139 s |
| 200 000 such segments, filled | 41% | 9.6 s |

The first three rows mean bug_0205 isn't closed: a round-capped dash
costs 250 times a butt-capped hairline's. The rest was there at
`f76b320`. These draw on a task or the loader's thread, not the main
thread.

## Root cause

`CostWalk::path` charges segments, dashes and the path's bounding box
once per paint. tiny-skia's time follows the covered area summed over
every subpath, dash and cap, and the edge crossings per row.
bug_0205's `DASH_COST` was calibrated on butt-capped hairlines.

## Fix (proposed)

Charge each dash and each subpath its own stroked area (length × width
plus caps), and a filled path its segments × the rows they span, not
only its bounding box. One model of cost per primitive rather than a
constant per reported case; test it with a search for the worst
accepted input.
