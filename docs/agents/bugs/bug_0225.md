# bug_0225 — `get`'s `default` argument isn't in the template check's value bound

## Symptoms

`s` is a 10 MB string (100 000 appends of 100 bytes; accepted, it's under
`MAX_TEMPLATE_VALUE_BYTES`). Then:

```
{% set y = {'a': 1} | get(key='b', default=s) %}
{% set z = y ~ y ~ y ~ y ~ y ~ y ~ y ~ y %}
```

is accepted with an output bound of 146 bytes and renders `[80000000]`.
Sixteen `{% set y = y ~ y %}` after the `get` (655 GB) are accepted too.
The same without `get` is refused (`ValueTooLarge`).

## Root cause

`filter` maps `get` to `x.element()` in its `"first" | "last" | "nth" |
"get"` arm and never reads the `default` argument. Tera returns the
default when the key is missing (`filters.rs:647`), so the result can be
any value the template holds, while the analysis thinks it's an element
of a one-entry map.

## Fix (proposed)

`get`'s bound is `x.element().max(default)`. The review found this one
by reading, not by enumeration: add a test that walks every built-in
filter's and function's arguments against the model, so an argument
that can become the result is never dropped.
