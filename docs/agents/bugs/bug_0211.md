## Symptoms

Layout harness, release; N paragraphs each with its own inline `<svg>`,
100 idle frames, no build:

| distinct documents | 100 frames | text-only page |
|---|---|---|
| 250 | 123 ms | 117 ms |
| 500 | 140 ms | 121 ms |
| 1 000 | 197 ms | 129 ms |
| 2 000 | 384 ms | 144 ms |

The extra is 0.05, 0.19, 0.68, 2.4 ms per frame — quadratic. A page of
per-row sparklines is the realistic case.

## Root cause

`rasterize_svg_images` asks `InlineSvgs::document_of` for every inline
span every frame, before it looks at the span's `SvgRaster`; that locks
the cache and scans all its entries (`svg.rs:925-935`, `:1182`).
`finish_inline_svgs` also rebuilds a set of every `InlineImage` each
frame.

## Fix proposed by the review

A second map, image id → document; skip the lookup when the span's
`SvgRaster::source` is still its image.

## Fix

`InlineSvgs` keeps a map image → document (filled when an entry gets its
`SvgDocument`, pruned with the entry), so `document_of` is a lookup; and
`rasterize_svg_images` asks only for a span whose `SvgRaster` doesn't
already name the document of its source.

Measured with the review's probe (release, layout harness, 100 idle
frames; a temporary test, since removed), the extra over a text-only
page per frame:

| distinct documents | before (review_0007) | after |
|---|---|---|
| 250 | 0.05 ms | 0.03 ms |
| 500 | 0.19 ms | 0.05 ms |
| 1 000 | 0.68 ms | 0.13 ms |
| 2 000 | 2.4 ms | 0.25 ms |

Linear now (the per-frame span walk remains); it was quadratic.
