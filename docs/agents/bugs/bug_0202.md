## Symptoms

- `width="256px"`, `"+5"`, `"12.9"`, `" 7"` or an entity-encoded value
  fell back to the default 300 × 150 (browsers read 256, 5, 12, 7).
- `<p>Map: <canvas>fallback</canvas></p>` showed "fallback" in the
  paragraph; browsers never show canvas fallback content.

## Root cause

`intrinsic_size` read the raw attribute with `trim().parse::<u32>()`
instead of HTML's rules for parsing non-negative integers, without
decoding character references. A canvas inside text was walked like an
unknown inline tag, so its children became text runs.

## Fix

`canvas::dimension` implements HTML's rules (ASCII whitespace, an
optional sign, digits up to the first non-digit, `0..=i32::MAX` as the
attributes reflect as `unsigned long`) over the decoded value. `run_walk`
skips a `<canvas>` inside text with a `debug` line (it still has no box
there: only a canvas directly in a container is a node).
