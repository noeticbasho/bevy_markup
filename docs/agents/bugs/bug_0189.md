## Symptoms

A 1000-rect `<marker>` set as `marker-mid` on a path of 4000 vertices
(44 KB) didn't finish converting in 120 s (ASan build).

## Minimal reproduction

```xml
<defs><marker id='m'><rect width='1' height='1'/> ×1000</marker></defs>
<path marker-mid='url(#m)' d='M0 0 1 1 1 1 … (4000 vertices)'/>
```

## Root cause

usvg's `marker::resolve` calls `convert_children` on the marker once per
vertex (`draw_markers`): 4·10⁶ rects. Marker properties are inherited
(`find_attribute`), so one `marker-mid` on a group applies to every path
below it, `<use>` copies included. Markers can nest: usvg only refuses to
re-enter the same marker.

## Fix

The bound's inheritance walk carries each element's inherited markers down
to its shapes. Each shape gets an edge to each marker, weighted by the
shape's segments + 2, so the marker's content counts once per start,
vertex and end. Segment counts come from the path data (see bug_0190).
