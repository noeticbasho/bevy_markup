## Symptoms

```xml
<filter id='f'><feMorphology radius='1e49'/></filter>
<rect width='8' height='8' filter='url(#f)'/>
```

Every build: `called Option::unwrap() on a None value` in usvg
(`parser/filter.rs:1028`). `svg::guarded` turned it into
`SvgError::Panicked`, a failed load; the fuzz target aborted on it.

## Root cause

usvg 0.49 `convert_morphology` reads `radius` as `f32`s (`1e49` becomes
infinity) and, when both are non-negative, unwraps
`PositiveF32::new(r × scale)`, which is `None` for a non-finite value
(UPSTREAM U30). `scale` is 1 in user space, or the element's bounding box
under `primitiveUnits="objectBoundingBox"`. There, a finite radius can
overflow too: radius 2 on a 2·10³⁸-wide box panicked the same way.

## Fix

`check_values` reads `radius` as usvg does (the whole list or nothing, one
number or two, only when both are non-negative) and refuses one that isn't
finite as `f32`. A finite radius times a huge box is bounded by bug_0197's
fix (ADR 0042: the radius counts in `Bounds::regions`). The first version
(`8184761`) instead refused a radius above 1 whenever any element used
`objectBoundingBox` primitive units, over-refusing ordinary radii in such
documents; ADR 0042 replaced that rule.

Probing the fix found bug_0197 (a filter on a box wider than ~2.8·10³⁸
panics before any primitive).
