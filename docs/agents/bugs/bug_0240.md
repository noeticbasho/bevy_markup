## Symptoms

The loader accepted this and displayed `25600000`: the intermediate
string exceeded the 16 MiB value limit. Twelve doublings also passed the
old check (409.6 MB if rendered; that variant was not rendered).

## Minimal reproduction

```python
key = 'k' * 100_000
source = ("{% set m = {'" + key + "': 1} %}"
          "{% for k,v in m %}{% set s = k %}"
          + "{% set s = s ~ s %}" * 8
          + "<p>{{ s | length }}</p>{% endfor %}")
```

## Root cause

Ordinary map expressions counted key bytes in the map's total size,
but not in its element bound. `loop_scope` used that element for both
key and value variables, so a long key paired with `1` looked tiny.

## Fix

`entries` now takes the maximum of value size and key length in
`out.elem`, matching the existing literal-map path. Map spreads inherit
that bound. This conservatively bounds both iteration variables and
also covers comprehensions over maps without changing public APIs.

## Validation

The new review_0009 regressions pass with the fixes. With the fixes
removed (for FTL, retaining the new error type but disabling enforcement),
all eight new regression tests failed, including the real-loader and
focus/activation tests. Full CI and a 15-minute honggfuzz campaign are
run after committing the fixes, at the user's request; their results
are reported by the fix session, not assumed here.
