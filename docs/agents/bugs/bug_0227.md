## Symptoms

Release build:

| template (outer loop count N) | check: steps at N = 100 000 | measured |
|---|---|---|
| `{% for i in range(end=N) %}{% set x = range(end=100000) %}{% endfor %}` | 500 003 (1.5% of the budget) | N = 1 000: 2.59 s; 4 000: 10.4 s |
| `{% set big = range(end=100000) %}` … `{% if 100001 in big %}` in the loop | 800 006 | N = 1 000: 0.25 s; 4 000: 0.99 s |
| `{% set_global s = s ~ '<100 bytes>' %}` in the loop | 600 024 | N = 100 000: 13–17 s |

The first two scale linearly in N: about 260 s and 25 s at the accepted
N = 100 000 (extrapolated). The third ran at 100 000: a linear
accumulator copies the whole string on every append, so the form the
check was built to accept is quadratic in time.

## Root cause

Only `filter` charges for size (`x.bytes.c / 16`). `range()`, `~`, `in`,
array spreads and comparisons are one tick each, whatever they build or
scan.

## Fix

Building or scanning a value is charged by its size, as filters were:
a binary operator charges both operands' bytes ÷ 16 (concatenation
copies them, `in` and comparisons scan them), and arrays, maps, slices,
comprehensions and calls (`range`) charge what they build; a filter also
charges its result. An accumulator appended in a loop is charged its
bound size every iteration, so its quadratic copying is counted.
