## Symptoms

```
{% set_global n = 0 %}{% for g in groups %}{% for c in g.cards %}{% set_global n = n + 1 %}{% endfor %}{% endfor %}{{ n }}
```

is refused: ``refused: `n`, set with `set_global` in a loop, could grow
faster than linearly``. The same happens with `names = names ~ c.name`.
One loop level is accepted. This loaded at `f76b320`; a refused template
fails its asset load.

Also refused, though ADR 0044 lists them as accepted costs:
`{{ text | replace(from='{name}', to=player) }}` (how a page fills a
placeholder in a context string) and `{{ items | join(sep=sep) }}`: two
context values in one filter.

## Root cause

The review's reading (not confirmed by a fix): `growth` gives each
carried variable two symbols (bytes, items) and builds the inner loop's
result from `start = before.bytes.max(before.items)`, so the outer pass
sees two of its own symbols in one value and counts two copies.

## Fix

`growth` counts a carried value's copies per *variable*, the largest
multiplicity among that variable's two symbols (bytes, items), not per
symbol: a nested loop's result `max(bytes, items)` of one variable is one
copy. The filters combining two context values
(`replace(from=…, to=player)`, `join(sep=sep)`) stay refused: their
results grow with the product of two context values, which is what
ADR 0044 refuses (`AppSquared`); a page fills placeholders with Fluent
arguments instead.
