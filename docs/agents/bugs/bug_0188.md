## Symptoms

The fuzz target asserts that each input finishes within 5 s. This one was
refused as too expensive to draw, which is correct, but only after 8.8 s.
Locally, under ASan, the depth check took 0.5 ms, usvg's conversion 1.7 s
and the cost estimate 21 ms. The harness parses each input twice (the
inline path and the file path).

## Minimal reproduction

```xml
<defs><g id='g0'><rect width='1' height='1'/></g>
<g id='g1'><use href='#g0'/> ×10</g> … <g id='g5'><use href='#g4'/> ×10</g></defs>
<use href='#g5'/>
```

That's ten `<use>`s per level and 10⁵ rects, about 1 KB. Conversion took
0.69 s in release.

## Root cause

usvg copies a `<use>`'s target into its tree for every `<use>`, then
converts each copy. Its only bound counts tree nodes (a million), so a
fan-out under it converts at about 7 µs per node in release. The loader
checked recursion depth before conversion and render cost after it, but
nothing bounded the conversion itself.

## Fix

`svg_bounds::bounds` counts every element's instances over the reference
graph (paths from the root, `<use>` copies included) and sums their work.
A document over `MAX_SVG_WORK` fails with `SvgError::TooLarge` before
usvg runs. Details and calibration: ADR 0040.
