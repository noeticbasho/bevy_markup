## Symptoms

A large or costly inline `<svg>` text is drawn on a task, which reserves
its raster bytes there. If the reservation fails, the task returns an
error and the entry stays in `entries` with no image, outside
`over_budget`. Freeing the budget (`over_budget.clear()`) doesn't bring
it back while the page keeps showing it. The synchronous path retries.
Found by reading; not probed.

## Root cause

Only the synchronous path records a budget refusal in `over_budget`;
the task path turns it into a plain draw error.

## Fix (proposed)

Have the task report a budget refusal distinctly and record the entry in
`over_budget` like the synchronous path, so a freed budget retries it.
