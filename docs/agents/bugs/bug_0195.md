## Symptoms

```xml
<filter id='f'><feConvolveMatrix order='65536'/></filter>
<rect width='8' height='8' filter='url(#f)'/>
```

Debug builds: `attempt to multiply with overflow` in usvg
(`tree/filter.rs:459`, or `parser/filter.rs:674` when a `kernelMatrix` is
present). `svg::guarded` turned it into `SvgError::Panicked`, a failed
load; the fuzz target aborted on it.

## Root cause

usvg 0.49 multiplies `order`'s columns and rows as `u32` unchecked
(UPSTREAM U29). Release builds wrap instead, which can make usvg accept a
huge kernel with no data. The render-cost estimate multiplies the sides in
`f64` and refuses such a kernel before resvg draws it [reading the code;
not observed in a release build].

## Fix

`check_values` reads `order` as usvg does: the first number saturated to
`i32`, the second defaulting to the first, a non-positive side keeping
usvg's 3. If both sides are positive and their `u32` product overflows,
it refuses with `SvgError::OutOfRange`. `OutOfRange` gained a `reason`, so
its message fits both of its checks.
