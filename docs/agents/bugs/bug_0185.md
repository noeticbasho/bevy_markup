## Symptoms

`<p>A <br/> B</p><p>C <b/>D</p>` built one paragraph, "A BC D". With a
space (`<br />`) or an attribute (`<b x="1"/>`) it built two, as it
should.

## Root cause

`tl` (astral-tl 0.8.1, `util.rs` `IDENT_CHARS`) counts `/` as a name
character. `parse_tag` reads the tag name with `read_ident`, so `<b/>`
is an element named `b/`. The self-closing check that follows finds no
`/`, and since `b/` isn't a void tag, it stays open: everything after it,
closing tags included, nests inside it. `tl` probes:

| source | `tl` reads |
|---|---|
| `<p>A <b/> B</p><p>C</p>` | `p` > "A ", `b/` > " B", `p` > "C" (one tree) |
| `<p>A <br/> B</p><p>C</p>` | the same with `br/` |
| `<svg><rect/></svg><p>C</p>` | `svg` > `rect/` > `p` |
| `<b />`, `<b x="1"/>`, `<rect width="1"/>` | correct |

A value-less attribute before `/>` does the same (`<input disabled/>`
has an attribute named `disabled/`, and no self-close).

## Fix

`template::normalize_self_closing` puts a space before a `/>` that
directly follows a tag name or an attribute name, the spelling `tl`
parses. It skips comments, quoted values and unquoted values (HTML reads
`<a href=/x/>`'s value as `/x/`). `HtmlDocument::parse` and
`walk_translation` run it before `tl`. Text without such a tag is
borrowed, not copied.

`tl` honors `/>` on every element, as it already did for `<b />`. HTML5
ignores it on non-void HTML elements (`<b/>` opens a `b`), but honors it
in SVG and MathML. That's unchanged behavior, now consistent for both
spellings.
