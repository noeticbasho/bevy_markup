## Symptoms

A 200 × 100 camera canvas, then `class='hidden'` (`display: none`): the
camera's image goes from `(200, 100)` to `(1, 1)`; `shown("map")` is
false. `HtmlCanvases::shown`'s docs say the opposite: "A camera keeps
rendering while nothing shows it; turn it off … where the last frame
needn't be kept." An app using the image elsewhere (a material, a
minimap) gets one pixel.

## Root cause

With no visible canvas, the first one in document order still owns the
camera (`.unwrap_or(&list[0])`, `canvas.rs:282`) and keeps its
`ViewportNode`. `display: none` lays it out at 0 × 0, and Bevy's
`update_viewport_render_target_size` resizes to `size.max(UVec2::ONE)`.

## Fix proposed by the review

An invisible canvas owns nothing (`camera: None` while no candidate is
visible).

## Fix

Only a canvas that's visible and within `MAX_CANVAS_SIDE` can own its
camera; with none, no canvas does, and nothing resizes the camera's
image. `HtmlCanvases::shown`'s docs now hold.
