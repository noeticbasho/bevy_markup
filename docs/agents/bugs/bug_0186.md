## Symptoms

`<p>E <svg width="64" height="64"><filter id="f"><feTurbulence
numOctaves="1000000"/></filter>…</svg> F</p>` dumped `"E "`, `"" img
64x64`, `" F"`: an empty 64×64 box in the line. The same SVG as an
`<img>` fails its load and takes no space.

## Root cause

`InlineSvgs::image` estimated the cost only against `INLINE_SYNC_COST`
(drawn during the build, or not). Anything above went to a background
task, which then refused it against `MAX_SVG_COST`. By then the build had
the reserved handle and the intrinsic size, so it sized the box, and the
handle was never filled.

## Fix

Estimate against `MAX_SVG_COST` while collecting. Over it, return `None`
(the element shows nothing, as a refused `<img>` does). Under
`INLINE_SYNC_COST`, draw during the build; between the two, draw on a
task.
