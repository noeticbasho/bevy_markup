## Root cause
The skeleton aligns sibling lists by position only. At the root it zips
the old and fresh children, so after an insertion every later row pairs
with its neighbour: unclean, so `Ctx::cull` refuses to cull it
(bug_0161). A nested container whose child count changed isn't paired at
all, so its subtree's heights drop and its frame stops culling. Only a
removal at the root's end is free.

## Fix (ADR 0033)
- Sibling lists whose count changed align by their common head and tail
  (`align_siblings`: identical source from each end, the middle by
  position), at the root and in nested containers; the container itself
  is paired (not clean), and an `li` moved to another ordinal leaves the
  clean set (its marker number changed). Removals were then cheap.
- Insertions still built the rest: the new element's unknown height
  invalidated the cursor. An unmeasured element now advances the cursor
  by its measured siblings' mean height (`WindowCtx::estimate`); a frame
  with no measured child, or an untrackable (`positioned`) child, still
  invalidates. A wrong estimate is bug_0170's one-frame lag.
