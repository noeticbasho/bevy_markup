## Symptoms

`CanvasSource::Camera` over a `RenderTarget::Image` of a reserved
(never inserted) handle: `called Option::unwrap() on a None value` on
the compute pool, the first frame.

## Root cause

Bevy's resize ends in `images.get_mut(image_handle).unwrap()`
(bevy_ui 0.20.1 `widget/viewport.rs:188`). `sync_canvases` gates the
size but not the image's presence before it inserts the `ViewportNode`.

## Fix proposed by the review

Check the target (`targets` + `Assets<Image>::contains`) before the
`ViewportNode` goes on; leave the canvas unbound until the image exists.
Upstream: UPSTREAM.md U38.

## Fix

`sync_canvases` binds a camera's viewport only while its target image is
in `Assets<Image>`; until then the canvas shows nothing, and it binds
the frame the image exists. Bevy's own unwrap stays (UPSTREAM U38).
