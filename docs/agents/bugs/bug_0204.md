## Symptoms

With `svg-text`, bug_0200's huge-pattern document with its `<rect>`
replaced by text passes the cost estimate and aborts the process when
drawn (64 × 64, Bevy's default font registered):

```xml
<pattern id='p' width='1e4' height='1e4' patternUnits='userSpaceOnUse'>
  <rect width='1' height='1'/></pattern>
<text y='8' font-size='8' fill='url(#p)' transform='scale(100)'>A</text>
```

| document | estimate (limit 134 217 728) | draw |
|---|---|---|
| the `<rect>` (bug_0200) | 2 000 000 110 904 | refused |
| the `<text>` | 8 384 | `memory allocation of 4000000000000 bytes failed`, SIGABRT |

## Root cause

`CostWalk::node` charges a text node `NODE_COST` and stops
(`usvg::Node::Text(_) => self.add(NODE_COST)`, `svg.rs:1690`). resvg
draws the text's flattened group: one path per glyph, with the text's
paint. bug_0200's tile charge lives in `CostWalk::path`, which those
paths never reach. `ExtentWalk` walks `text.flattened()`, but it bounds
reach, not tile size.

## Fix proposed by the review

Walk `text.flattened()` in `CostWalk` as `ExtentWalk` does; this also
fixes bug_0206. The `svg` fuzz target can't find this class (bug_0221):
test it with a unit probe under `svg-text`.

## Fix

`CostWalk::node` walks a text node's `flattened()` group, so each glyph
path is charged like any path: its area, and a pattern paint's tile at
its drawn size (bug_0200's charge).
