## Symptoms

```xml
<filter id='f'><feGaussianBlur stdDeviation='1.4e31'/></filter>
<rect width='40' height='40' filter='url(#f)'/>
```

Where overflow checks are on (debug builds, fuzzing): `attempt to add
with overflow` in resvg 0.49 `filter/box_blur.rs:48`. `svg::guarded`
turned it into `SvgError::Panicked`, a failed draw; the fuzz target
aborted on it.

## Root cause

resvg scales the deviation by the group's transform
(`filter/mod.rs` `resolve_std_dev`); from 2.0 px it uses the box blur,
whose `create_box_gauss` takes the ideal box width
`sqrt(12σ²/5) + 1` as an `i32` (saturating at `i32::MAX` once σ² is
infinite) and adds 2 unchecked (UPSTREAM U32). The overflow needs σ of
~1.4·10⁹ px. Release builds wrap to a negative box, cast to a huge
`usize` radius [reading the code; not run in release]; the blur loops
are capped by the image size, so a large finite σ doesn't hang.

## Fix

`check_extent`'s walk (before drawing, through every transform resvg
applies) computes each `feGaussianBlur`'s and `feDropShadow`'s
deviation × the transform's scale, as resvg does, and refuses one past
`MAX_SVG_BLUR` = 2²⁰ px with `SvgError::TooBlurred`. That's far below
the overflow and far beyond any layer resvg blurs (5 × `MAX_SVG_SIDE`).

The local 30-minute run on the same commit (3.1M inputs) didn't reach
it; the CI job did in its first minutes.
